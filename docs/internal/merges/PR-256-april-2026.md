## 6. Post-merge

After the PR is approved and merged with **"Create a merge commit"** (do not squash — preserves upstream history for the next merge):

1. **Integration deploy** — `deploy-integration.yml` triggers automatically. Watch for migration `257-add-custom-function-is-mutation` running cleanly in the WAB pod logs.
2. **Republish hostless** — GitHub Actions → "Publish Hostless Packages" → run for `integration`. **Required**: every CustomFunction in every hostless bundle gains `isMutation: false`. Without this republish, integration projects will see stale hostless bundles whose CustomFunctions lack the field, and PR #2662's `isQuery`/`isMutation` filtering will misclassify them.
3. **Smoke test integration** — load a known EP project, exercise an EP commerce interaction, confirm a server query page SSRs.
4. **Promote to prod** — merge `main → prod` MR in `plasmic-terraservices`. After deploy completes, update `container_image` in `services/publish-hostless/config/prod-eu.tfvars` and `prod-us.tfvars`, merge that MR to trigger GitLab pipelines.
5. **Verify prod** — spot-check Studio + EP commerce on EU and US.

## 7. EP commerce package follow-up (not blocking)

Once the merge is in, open a follow-up PR to `plasmicpkgs/commerce-providers/elastic-path/` adding `isMutation: true` to every write-side `registerFunction` call (`addToCart`, `updateQuantity`, `removeFromCart`, `checkout`, `applyPromotion`, etc.). Read-side functions (`searchProducts`, `getProduct`, `getCart`) keep `isQuery: true`. This is what makes those functions appear in the interaction-expression picker (PR #2662) instead of the data-query picker.
